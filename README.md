# NodeSeek 个人版 0.1.6

从零编写的个人用户脚本，只包含三个功能：

1. **自动签到**：每天按北京时间尝试一次，默认随机鸡腿。跨标签互斥，失败后不后台反复请求，可手动重试。
2. **用户资料增强**：淡绿资料卡展示等级、鸡腿、星辰、主题数、回复数、粉丝、注册天数、身份标签和参考信任分；用户名旁显示参考分/天数/等级徽章；支持复制名字、本机备注、关注/屏蔽、私信，以及原生转账入口。
3. **聊天式私信**：自己的资料卡新增私信入口；浅灰双栏消息面板、联系人头像、最近消息搜索和分页、左右聊天气泡、简单 Markdown、按需加载图片、Enter 换行、Ctrl/⌘+Enter 发送、手机布局、深浅色跟随论坛。

## 安装

[安装 / 更新最新版](https://raw.githubusercontent.com/Aurivian11/nodeseek-personal/main/dist/nodeseek-personal.user.js) · [GitHub 仓库](https://github.com/Aurivian11/nodeseek-personal)

安装 Tampermonkey 后打开上面的安装链接，确认安装或更新「NodeSeek 个人版」，再刷新 `https://www.nodeseek.com/`。如果浏览器只显示源码，可将全部内容复制到 Tampermonkey 的现有脚本编辑器并保存。设置窗口标题可确认版本为 `0.1.6`。

**从本地版 0.1.5 或更早版本升级，需要先手动安装这一次。** 0.1.6 起配置了本仓库的 `@updateURL` / `@downloadURL`；以后发布更高版本时，Tampermonkey 可按自己的更新设置检查并安装，也可在其管理面板手动检查更新。旧版缺少更新地址，无法自行发现这个仓库。更新机制见 [Tampermonkey 官方说明](https://www.tampermonkey.net/documentation.php?q=update_url)。

右下角会出现「设置 / 签到 / 私信」，自己的资料卡统计区下方也有「私信」。页面加载完成前可能暂时看不到按钮。如仍未显示，请确认脚本启用、扩展允许访问 NodeSeek，并开启 Chrome 的「允许用户脚本」。

如已启用原 NodeSeek++，先停用它，避免重复签到和界面冲突。此仓库不上传用户设置、Cookie、私信、备注或真实页面截图。

默认开启自动签到、用户资料卡、用户名徽章和聊天面板；签到为随机鸡腿。升级到 0.1.2 时会一次性把旧版保存的固定方式改为随机，以应用本次用户选择；此后在设置中自行选择的方式会保留。已经完成的当日签到不会重复执行。自动签到需要浏览器支持 Web Locks；不支持时保留手动签到。页面处于后台时不会自动签到。

资料卡可用键盘 Tab 聚焦用户名打开，方向下键进入卡片，Esc 关闭。数据缺失显示「未知」。徽章仅为视口附近的作者获取资料，共享有界请求队列、同用户去重和内存缓存；可在设置中关闭。

参考信任分是本地公开资料摘要，**非官方评级，不代表交易信用**，也不沿用其他脚本的分数公式。六项分数分别为「权重 × √(实际值/上限)」，达到上限后不再增加：注册730天40分、主题100帖15分、评论1000条20分、粉丝50人10分、鸡腿5000枚10分、星辰200枚5分，总计0–100。任何必需数据缺失时不评分；悬停或点击卡片分数可查看说明。

关注和屏蔽仅在点击后核对站点状态并请求，屏蔽另需确认。转账按钮只打开论坛现有转账窗口，不自动填写收款人或金额，也不直接调用资金接口，必须在原站窗口核对并完成操作。

私信只有明确点击发送或快捷键操作才发送。如果发送超时或结果不明，会保留草稿并锁住重复发送；先刷新聊天记录，再选择「已确认发送，清空草稿」或「已核对未发送，解除防重」。

直接打开 `/notification#/message` 或某个私信会话、刷新该页、页面内切换到私信时，会自动显示聊天面板。「原版页面」链接带 `native=1`，可临时使用原生界面。主动关闭面板后，同一路由上的普通页面更新不会强制重新打开；右下角「私信」可以随时手动打开。

## 数据和权限

- 只匹配 `https://www.nodeseek.com/*`，不在 iframe 中运行。
- 只申请三个权限：`GM_getValue`、`GM_setValue`、`GM_registerMenuCommand`。
- 没有 `@connect *`、`unsafeWindow`、外部运行依赖和统计上报。更新检查仅由脚本管理器使用本仓库的固定 GitHub 地址。
- 使用同源 `fetch`，接口按功能白名单限制，禁止跟随请求重定向。
- 每次签到、发送私信和标记已读前，读取同源首页核对当前登录账号；识别失败或发现换号时停止操作，并提示刷新页面。
- 设置、签到日期及用户备注保存到脚本管理器存储；资料请求结果仅作页面内存缓存。
- 聊天记录不写入 IndexedDB、localStorage 或脚本存储。关闭面板后清除已加载记录；草稿和发送防重状态只保留在当前页面内存，刷新或关闭页面后消失。
- 私信文本用 DOM 文本节点构建，不插入消息 HTML。消息里的外部图片默认不加载；点击「加载图片」后才向图片服务器请求，且不携带 Referer。
- 未加入 AI、图床上传、自动翻页或内容过滤；转账由论坛原生窗口处理。

## 开发与验证

浏览器运行脚本不需要安装 Node.js 或依赖。开发使用 Node.js 24（至少 24.15.0）。以下命令仅供修改和运行测试：

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm test
npm run preview
```

预览地址：`http://127.0.0.1:8765/preview`。预览只绑定本机，使用虚构联系人和内存消息，不访问真实论坛；预览里的「发送」不会给任何人发私信。

源码：`src/00-core.js`（设置、账号识别与同源请求）、`src/15-profile-model.js`（资料与参考分）、`src/18-profile-actions.js`（资料卡操作）、`src/20-account.js`（签到与资料卡）、`src/25-badges.js`（行内徽章）、`src/28-inbox-entry.js`（个人卡私信入口）、`src/30-messages.js`（私信）、`src/90-main.js`（入口）。构建脚本只拼接这些本地文件。

验证覆盖：接口白名单、账号变更保护、恶意 HTML 文本、图片按需加载、签到跨标签锁、失败不自动重试、聊天响应竞态、发送失败保留草稿、重复发送保护、弹窗关闭重开、模态窗口内资料卡层级、构建范围，以及直达地址/路由/延迟挂载等入口。0.1.2 新增随机签到默认与迁移、资料缺失/分数边界、四动作触发、徽章可见时请求/去重/排除非作者的测试。0.1.3 增加资料卡入口资格、重绘去重、只读打开、消息搜索、同源头像、全已读取消/成功/失败及迟到请求、服务端会话身份确认的测试。共 44 项离线测试通过。另在本地浏览器检查桌面、390px 手机宽度和深浅色布局，并只读核对了真实 NodeSeek 页面上的账号卡片结构与公开资料接口字段。

自动化测试中的请求均为模拟。真实站点此前已确认脚本启动、联系人列表读取及公开资料字段；本次新增功能通过模拟接口和浏览器预览验证，未在真实账号执行发送、批量已读、关注、屏蔽、转账或重新签到。用户需覆盖安装新版后生效。论坛实际接口和反爬验证仍可能影响使用。接口字段参考先前审计的 NodeSeek++ `26.1030.1015`，实现代码独立编写。

## 后续更新

以后维护此仓库，保留脚本名称 `NodeSeek 个人版` 与 namespace `local.nodeseek.personal`，以便更新已有安装。

1. 修改 `src/`，增加 `package.json` 的版本号，更新 README 版本与变更说明；依赖或版本变化后同步锁文件。
2. 运行 `npm ci --ignore-scripts`、`npm run build`、`npm test`。
3. 提交源码和 **两份**构建产物 `dist/nodeseek-personal.user.js`、`dist/nodeseek-personal.meta.js`。优先在分支通过检查后合并到 `main`。
4. GitHub Actions 会检查构建可复现与测试结果，不会自行修改源码、自动升版或提交文件。合并后固定安装链接提供新版，脚本管理器下次检查更新时即可发现。

不要只改 `dist/` 或只提升版本号而未重新构建。旧版快照、个人截图和本机配置不进入仓库。
